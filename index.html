HOW A BACKTEST WORKS

  1. ObserveSignal at close t
  2. ExecuteNext common close
  3. AccountCosts, cash & holdings
  4. InspectLedger + validation

This is a research app. It uses daily adjusted prices and simulated trades, so the results depend on the data and assumptions you choose.

A few decisions behind the code +

The maths lives outside the UI. I can check the portfolio and backtest calculations with small, repeatable inputs, without starting Streamlit or fetching market data.

A signal isn’t a trade. The backtest executes a decision at the next common close. It tracks drifting holdings, pays costs from the portfolio, and leaves unused capital in cash.

Fitting and testing are different steps. Walk-forward allocation uses earlier prices to estimate weights, then evaluates them on later observations. The choice of assets and data still affects what you can conclude.

Igloo02

An experiment in querying databases and files together.

With Igloo, I’m working on a small SQL engine in Rust using DataFusion and Arrow. It can query PostgreSQL and Parquet together, accept queries from PostgreSQL clients, and cache results in memory.

↓
Arrow record batchesIn-memory LRU + TTL cache

Igloo currently runs in one process. Distributed execution and Apache Iceberg integration are still on the roadmap.

A few decisions behind the code +

A faster query still has to give the same answer. DataFusion rechecks pushed filters locally. String ordering stays local because PostgreSQL collation can disagree with Arrow ordering.

The cache keeps Arrow batches. It shares the result representation used by the engine, with an entry limit, TTL, and LRU eviction.

It’s still an experiment. JSON change-event files invalidate the cache today. I’m also working on agent interfaces, broader ADBC support, and native CDC foundations in a separate draft preview.
